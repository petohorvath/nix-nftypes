# Changelog

All notable changes to nix-nftypes will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0] - 2026-10-29

The schema accepts what nft loads as written and rejects what it loads as something else ([ADR 0010](docs/adr/0010-accept-what-nft-loads-as-written.md)), the text renderer writes text that loads the same ruleset as the JSON form, or raises a Refusal, and the DSL follows one set of naming and argument conventions ([ADR 0009](docs/adr/0009-dsl-naming-and-argument-conventions.md)). Many of these changes break callers of the DSL, the schema types, and the text renderer.

### Upgrading from 0.1.0

Names removed without a replacement, such as the builders of commands nft rejects or mishandles, are listed under Removed only; the two compatibility helpers that encoded one consumer's conventions are in the table, pointing to a copy in the caller's code.

### Added

- `validate type value` checks a value against a schema type and returns it unchanged, ready to render. It forces the whole value, so every check runs, and replaces the `lib.evalModules` pattern the docs showed.
- `add.<kind>`, a command builder for each of the 16 add-object kinds, like `create.<kind>`.
- Sets and maps accept a `comment`, so `types.ruleset` validates the Read-back of a commented set or map. nft's JSON parser ignores it on input.
- ct helper, timeout, and expectation objects accept `l3proto = "inet"`, which nft lists for one in an inet table. Their `l3proto` has its own type, `types.ctL3Protocol`, with values under `enums.ctL3Protocol`.
- `types.deleteObject` and `types.destroyObject`, the object unions of `delete` and `destroy` commands, and `types.readBackObject`, a bare listed object in a ruleset, as `nft -j list` emits.
- `types.insertObject`, `types.replaceObject`, and `types.renameObject`, the object unions of `insert`, `replace`, and `rename` commands, and the bodies they take, `types.objectBodies.insertRuleBody`, `replaceRuleBody`, and `renameChainBody`.
- `list.ruleset`, beside `flush.ruleset`: `list.ruleset { }` lists every table, and `list.ruleset { family = "ip"; }` one family's. `types.listObject` takes `ruleset`, whose body is `types.objectBodies.listRulesetBody`.
- `types.tunnelErspanDirection` and `enums.tunnelErspanDirection`, the capture directions `ingress` and `egress` of an ERSPAN version 2 tunnel's `dir`, which took an unnamed enum.
- `types.expressionBodies.elemReadBackBody`, an element as Read-back lists it, with the statement keys nft lists beside `val`: `counter`, `quota`, `limit`, and `last`. `types.readBackObject` takes it for the elements of a listed set, map, element, or rule, anonymous sets included, so `types.ruleset` validates the Read-back of a set whose elements carry stateful statements. Input commands and `types.expression` take `elemBody`, which rejects those keys, since nft's JSON parser ignores them on input and loads the element without its counter.
- The log, masquerade, redirect, queue, and reject statements accept the `null` body that nft lists for one with no options, so `types.ruleset` validates its Read-back. Text renders it as the bare statement, such as `log`. Their bodies, `types.statementBodies.logBody`, `masqueradeBody`, `queueBody`, and `rejectBody`, accept `null` too.
- `types.byteUnit` and `types.limitRateUnit`, with their values under `enums`: nft's byte units, `bytes`, `kbytes`, and `mbytes`, and a limit's rate units, which add `packets`. `types.ctKey` and `enums.ctKey` hold the conntrack keys nft's JSON parser looks up.
- `types.statementBodies` holds the body of every statement tag that takes more than `null`, the same type `types.statement` takes for that tag. It adds `objectReferenceBody`, which `ct helper`, `ct timeout`, `ct expectation`, `secmark`, and `tunnel` share: a Reference, the object's name or a map expression that selects it. It also holds `verdictTargetBody`, the body of `jump` and `goto`, the same type as `types.expressionBodies.verdictTargetBody`. `accept`, `drop`, `continue`, `return`, and `notrack` take only `null`, so they have no body there and keep `types.nullLiteral`.
- `types.flowtableHook` and `enums.flowtableHook`, which hold the one hook nft accepts for a flowtable, `ingress`, and type a flowtable's `hook`.
- A DSL chain's `prio` takes a Symbolic priority, such as `"filter"`, in a table tree's `chains` and in `add.chain` and `create.chain`. The DSL resolves it with `compatibility.priorityValue` for the chain's family and hook and emits the int, since nft's JSON `prio` is an integer only: a bridge chain's `prio = "filter"` emits `-200`. A symbol nft rejects at the hook throws the helper's message at the chain's `prio`, as in `nix-nftypes: dsl.table ip.t: chains.input.prio: family 'ip' has no priority 'dstnat' at hook 'input'. …`. A flowtable keeps an integer `prio`.
- `fields.th`, nft's transport-header ports `sport` and `dport`, which match whatever the transport protocol, and `fields.igmp`, IGMP's `type`, `mrt`, `checksum`, and `group`.
- `enums.payloadFieldsByProtocol`, the payload protocols nft's JSON parser knows, each with the fields it loads as written, in nft's spelling: `payloadFieldsByProtocol.ip` holds `"frag-off"`.

### Changed

- The unit fields take only nft's units, in statements and named limits alike: a limit's `rate_unit` takes `types.limitRateUnit`, and its `burst_unit` and a quota's `val_unit` and `used_unit` take `types.byteUnit`. They took any string: nft's JSON parser loaded an unknown unit as bytes, and text wrote it as given, which nft rejects, so `{ limit = { rate = 10; per = "second"; rate_unit = "furlongs"; }; }` validated and loaded as 10 bytes/second.
- A ct expression's `key` takes only nft's ct keys, `types.ctKey`. It took any string, which nft's JSON parser rejects with "Unknown ct key".
- An IPsec expression requires `dir`, a FIB lookup `saddr` or `daddr` among its `flags`, and a ct expression `dir` for the keys `saddr`, `daddr`, `proto-src`, `proto-dst`, `ip saddr`, `ip daddr`, `ip6 saddr`, and `ip6 daddr`. A ct expression takes `dir` only for these keys and `l3proto`, `protocol`, `packets`, `bytes`, `avgpkt`, and `zone`, the keys nft's JSON parser reads one for. `types.expression` and the bodies in `types.expressionBodies` reject a value that breaks these rules, and `expr.ipsec`, `expr.fib`, and `expr.ct` throw, naming the builder and the rule, as in ``nix-nftypes: dsl.expr.fib: not of type `fib body with saddr or daddr among its flags'.``. They accepted expressions nft rejects, such as `{ ct = { key = "saddr"; }; }` and `{ ct = { key = "state"; dir = "original"; }; }`.
- A ct expression has no `family`: `types.expressionBodies.ctBody` and `expr.ct` reject it, and the text renderer refuses one in raw input. nft's JSON parser ignores it and nft never lists it, so `{ ct = { key = "mark"; family = "ip"; }; }` validated and loaded without its family. A ct key carries its family in its name, as `ip saddr` does.
- The enum-extraction check compares the ct keys and the byte units with nftables' `ct_templates` and `data_unit` tables.
- `compatibility.prioritiesByFamily`, an attrset indexed by family and hook, replaces the `priorityIntsByFamily` function, and holds only the symbolic priorities nft accepts at each hook: write `prioritiesByFamily.bridge.input` for `priorityIntsByFamily "bridge"`. `priorityIntsByFamily` gave every family but bridge all six default symbols at every hook, though nft accepts, for example, only `filter` in the arp and netdev families and `dstnat` only at prerouting and output. [`docs/api.md`](docs/api.md) lists where nft accepts each symbol.
- The priority helpers take the hook and throw where nft would. `compatibility.priorityValue family hook priority` replaces `resolvePriority family priority`, and `compatibility.priorityName family hook priority` replaces `priorityNameOf family priority`. They throw on a hook the family lacks and on a symbol nft rejects at the hook: `resolvePriority "netdev" "mangle"` returned `-150`, and `priorityNameOf "bridge" "bogus"` returned `"bogus"`. `priorityName` returns an int whose symbol nft rejects at the hook unchanged, as nft lists it.
- Every compatibility helper throws on a family, chain type, or hook outside its table, naming the helper. `validChainPlacement "foo" "filter" "input"` returned `false`, so a typo read as an invalid placement.
- `compatibility.hooksByChainType.filter` lists every hook, instead of `null` for "any hook the family exposes".
- The compatibility tables and helpers read the families, chain types, and hooks they know from `enums`, so they cannot drift from `types.family`, `types.chainType`, and `types.hook`. `compatibility.familiesByChainType.filter` is `enums.family`, and lists the families in its order, `ip`, `ip6`, `inet`, `arp`, `bridge`, `netdev`, as an unknown-family error does.
- `integration-chain-placement` real-loads a filter chain at each hook of each family and each of nft's priority symbols, and checks that it loads exactly where `compatibility.prioritiesByFamily` lists the symbol.
- Flush commands are a `flush.<kind>` namespace like the other verbs: `flush.ruleset`, `flush.table`, `flush.chain`, `flush.set`, `flush.map`, and `flush.meter`. Each takes an object body, and `flush.ruleset { }` flushes every family. They replace `flushRuleset`, `flushTable`, `flushChain`, `flushSet`, `flushMap`, `flushMeter`, and the bare `flush` value.
- Every DSL field name is camelCase, and each field has one spelling:
  - `limit` takes `rateUnit` and `burstUnit`, and so do named limits in a table tree and `create.limit`.
  - `quota` takes `valUnit` and `usedUnit`.
  - `snat` and `dnat` take `typeFlags`.
  - A rule's statement list is `statements`, in `add.rule`, `insert.rule`, `replace.rule`, and a table-tree rule entry, `{ statements; comment?; }`: write `statements = [ … ]` for `expr = [ … ]`. The bare-list entry, `rules = [ [ accept ] ]`, is unchanged.
  - `setStmt`, `mapStmt`, and a set or map body take `statements` for `stmt`, and `meter` takes `statement`.
  - `rename.chain` takes `newName` for `newname`.
  - `reject` takes `code` for `expr`, the ICMP code: write `reject { type = "icmpx"; code = "admin-prohibited"; }`.
  - A JSON spelling, such as `rate_unit`, `gc-interval`, `expr`, `newname`, or `elem` in a set or map body, throws in a statement, a command builder, and a table tree alike, and points to the DSL name: ``rate_unit: is the JSON spelling; write `rateUnit` ``. An object body passed it through, so a body with both spellings dropped one value, and a statement rejected it as an unexpected argument.
- A field takes the DSL word for what it holds ([ADR 0009](docs/adr/0009-dsl-naming-and-argument-conventions.md)): `setStmt` takes `element` and `mapStmt` takes `key` for the JSON `elem`, so `mapStmt { op; key; data; map; }` reads like `expr.map key data`. A map body takes `dataType` for the JSON `map`, which holds the data type of the map's values, in a table tree and in the `<verb>.map` command builders alike: write `maps.m = { type = "ifname"; dataType = "verdict"; }` for `map = "verdict"`. `elem` in `setStmt` and `mapStmt` and `map` in a map body throw and point to the DSL name.
- A Table tree is stricter, and its errors say more:
  - A rule entry is `{ statements; comment?; }` or a bare list. Its `index` throws, as in ``nix-nftypes: dsl.table inet.fw: chains.input.rules.1.index: a Table tree lists a chain's rules in order, so a rule takes no `index`; …``, so every tree renders in `toText` and block form alike. Block form refused an `index` with the `rule index` Refusal, which is gone. `add.rule` and `insert.rule` keep `index`.
  - `dsl.table` marks the tree with `_type = "nix-nftypes.tableTree"`, the nixpkgs convention, for `__nftTable = true`. Cleaning strips it, so it never reaches JSON. A `_type` in the body throws, since the marker replaces it; it was accepted and dropped.
  - A module-system error inside a tree starts its option path with the tree, as in ``A definition for option `"dsl.table inet.fw".chains.input.prio' is not of type …``. It started `chains.input.prio`, which named no table.
  - An unknown key lists the keys a tree takes, and a kind's singular name points to its plural: ``unsupported key(s): set; a Table tree takes flags, comment, chains, …; write `sets` for `set` ``.
  - A quota object's `val`, the quota statement's word, throws and points to `bytes`, in a tree's `quotas` and in `add.quota` and `create.quota`. It failed as an option that does not exist.
- `expr.map key data` and `expr.payload protocol field` take positional arguments, like `vmap key data`.
- `flow` takes the flowtable name alone, with or without its `@`: write `flow "ft"` for `flow { flowtable = "ft"; }`. Its `op` had one legal value, `add`, which the statement still emits.
- `payload`, `payloadRaw`, and `payloadTunnel` sit under `expr` with the other expression constructors: write `expr.payload "tcp" "dport"` for `payload "tcp" "dport"`.
- `insert` and `replace` are `<verb>.<kind>` namespaces like the other verbs, `rename` included: write `insert.rule` and `replace.rule` for `insert` and `replace`. Their errors name `dsl.insert.rule` and `dsl.replace.rule`.
- The reset statement is `resetStmt`, like `setStmt` and `mapStmt`, and `reset` holds only the `reset.<kind>` command builders: write `resetStmt (expr.tcpOption { … })` for `reset (expr.tcpOption { … })`.
- `last` is a variant namespace like `counter`: write `last.auto` for the bare `last`, and `last { used = …; }` for `lastUsed …`. `last { }` throws and points to `last.auto`, because nft rejects an empty body.
- `match.in_` is the top-level operator `hasAnyFlag`, named for its test: it matches when any of the given flags is set, as in `hasAnyFlag tcp.flags [ "syn" "ack" ]`.
- The compatibility helpers sit under `compatibility`, beside the tables they read: write `compatibility.validChainPlacement` for `validChainPlacement`, and `compatibility.priorityValue` and `compatibility.priorityName`, which take the hook, for `resolvePriority` and `priorityNameOf`. Their errors name `compatibility.<helper>`.
- The body namespaces `types.expressions`, `types.statements`, and `types.objects` are `types.expressionBodies`, `types.statementBodies`, and `types.objectBodies`, so none differs by one letter from `types.expression` or `types.statement`. Every body type in them is named `<kind>Body`; a variant or a nested part of one tag's body puts its parent first, and the body of one command its verb ([ADR 0009](docs/adr/0009-dsl-naming-and-argument-conventions.md)):
  - `types.objectBodies`: `setObjectBody`, `mapObjectBody`, `counterObjectBody`, `quotaObjectBody`, `limitObjectBody`, `ctHelperObjectBody`, `ctTimeoutObjectBody`, `ctExpectationObjectBody`, `ctCountObjectBody`, `secmarkObjectBody`, `synproxyObjectBody`, `tunnelObjectBody`, and `meterObjectBody` drop `Object`, as in `setBody`. `tunnelVxlanNested`, `tunnelErspanV1Nested`, `tunnelErspanV2Nested`, and `tunnelGeneveOpt` are `tunnelVxlanBody`, `tunnelErspanV1Body`, `tunnelErspanV2Body`, and `tunnelGeneveOptionBody`. `rulesetBody`, the body of `flush ruleset`, is `flushRulesetBody`, so it no longer reads as the `types.ruleset` envelope. `types.insertObject`'s rule is `insertRuleBody`; `ruleBody` is the Read-back rule only.
  - `types.statementBodies`: `counterRefOrBody`, `quotaRefOrBody`, `limitRefOrBody`, `ctCountRefOrBody`, `synproxyStatementBody`, `setStatementBody`, and `mapStatementBody` are `counterBody`, `quotaBody`, `limitBody`, `ctCountBody`, `synproxyBody`, `setBody`, and `mapBody`. `ctCountBody` was the inline form alone; it now takes every form of the statement, a reference included, like `counterBody`.
  - `types.expressionBodies`: `tunnelExprBody` is `tunnelBody`, and `rawPayloadBody`, `namedPayloadBody`, `tunnelPayloadBody`, `rawTcpOptionBody`, and `namedTcpOptionBody` are `payloadRawBody`, `payloadNamedBody`, `payloadTunnelBody`, `tcpOptionRawBody`, and `tcpOptionNamedBody`, matching the DSL's `expr.payloadRaw` and `expr.tcpOptionRaw`.
- The enum and primitive types follow ADR 0009's names, in `types` and `enums` alike: `xfrmKey` and `xfrmDir` are `ipsecKey` and `ipsecDirection`, as the expression is `expr.ipsec`; `ngMode` is `numgenMode`; `perUnit`, which holds time units, is `timeUnit`; `policy` is `chainPolicy`, beside `chainType` and `setPolicy`; and `nftQuotedString`, which types only comments, is `types.comment`.
- The DSL's binary operators are camelCase, like `builtins.bitAnd`: `expr.bitand`, `bitor`, `bitxor`, `lshift`, and `rshift` are `expr.bitAnd`, `bitOr`, `bitXor`, `shiftLeft`, and `shiftRight`.
- `fields.tunnelMeta` is `fields.tunnel`, named for its JSON tag like `fields.ct` and `fields.meta`: write `fields.tunnel.id` for `fields.tunnelMeta.id`.

- `types.objectBodies.tunnelNestedBody` is `tunnelEncapsulationBody`, named for what a tunnel's `tunnel` field holds.
- A value outside `types.statementOf` or `types.expressionOf` fails with the restricted type's description, such as `statement (one of: "match")`. The module system rebuilds a type an option declares, which dropped the description, so the error read `attribute-tagged union with choices: match`.
- `types.statementOf` and `types.expressionOf` throw `nix-nftypes: types.statementOf:` or `nix-nftypes: types.expressionOf:` for a tag that is not a string, as in `statementOf [ 1 ]`, which failed with Nix's "cannot coerce an integer to a string". A non-list argument's error now says what it got.
- `types.statementOf` and `types.expressionOf` name their argument's entries tags, as GLOSSARY.md does: an unknown one throws `unknown statement tag(s): "x". Valid tags: …`, and an empty list throws `expected a non-empty list of statement tags, got an empty list`. They said `kind(s)` and `kinds list must be non-empty`.
- `docs/api.md` names every top-level, `dsl`, `dsl.expr`, and `compatibility` export, and the `public-surface` suite fails on one it leaves out. It documents the bodies and enums by pattern, and the quota statement's `val` and `used` beside the quota object's `bytes` and `used`. The docs and library comments use GLOSSARY.md's terms, such as Table tree and Variant namespace.
- `expr.ct`, `expr.rt`, and `expr.osf` take a key with its refinement, `dir`, `family`, or `ttl`. Without one they throw and point to the key's Field leaf: ``nix-nftypes: dsl.expr.ct: `expr.ct` builds a ct expression with a refinement; without one, write the Field leaf `fields.ct.mark` ``. Each key had two names, so `expr.ct { key = "mark"; }` built the same expression as `fields.ct.mark`.
- `expr.payload protocol field` takes only a protocol and field from `enums.payloadFieldsByProtocol`, and throws for any other, naming the builder and listing the valid ones: `nix-nftypes: dsl.expr.payload: unknown ip field 'fragOff'. Valid ip fields: version, …`. It took any strings, so `expr.payload "ip" "fragOff"` built a value that nft rejects on load. It also rejects `l4proto`, which nft's parser takes on `ip`, `ip6`, `gre`, and `gretap` but loads as other header bits, so `ip l4proto 6` loads as `ip version 0 ip hdrlength 6`; and the `vxlan` and `geneve` fields, which load only through `expr.payloadTunnel`. `expr.payloadRaw` still reaches any bits. The enum-extraction check compares the table with nftables' protocol table and each protocol's templates.
- The `stmt` of a set, a map, a set or map statement, and a meter takes only a Stateful statement: an inline `counter`, `quota`, `limit`, `ct count`, or `last`, as nft's `STMT_F_STATEFUL` marks one. This covers `statements` in `setStmt`, `mapStmt`, and a set or map body, and `meter`'s `statement`. They took any statement, so `{ log = null; }`, a verdict, and a Reference such as `{ counter = "c"; }` validated, which nft rejects with "Unsupported set statements array" or "meter statement must be stateful". Taking any statement also made the schema a cycle through the set, map, and meter bodies, so NixOS overflowed the stack rendering the documentation of an option typed `types.statement`, `types.command`, `types.ruleset`, or any type that reaches a set.
- An anonymous set or map, `{ set = [ … ]; }`, takes at least one element, in `types.expression` and in a vmap's or map lookup's data, and `inSet`, `notInSet`, `vmap`, `expr.map`, and `expr.set` throw on an empty list, pointing to `lib.optional`. nft rejects an empty one in JSON and text ("Invalid RHS of relational", "Illegal map expression data"), so `inSet tcp.dport cfg.allowedTCPPorts` built a ruleset that failed to load whenever the list was empty. A named set or map still takes `elements = [ ]`.
- A vmap's anonymous map and the elements of a map with `dataType = "verdict"` (the JSON `map`) take only `[ key verdict ]` pairs, whose value is `accept`, `drop`, `continue`, `return`, `jump`, or `goto`. `vmap` throws on a verdict written as a string and points to its builder, as in ``the value "accept" for the key 22 is a string, which nft's JSON parser rejects; write a verdict, such as `dsl.accept` or `dsl.jump "chain"` ``. They took any value: nft's JSON parser rejects `"accept"` ("Could not parse netfilter verdict"), while text loads it as the verdict.
- `types.expression` and text reject a range written as a string, two numbers or two IP addresses joined by `-`, such as `"1000-2000"` or `"10.0.0.1-10.0.0.5"`, and point to `dsl.expr.range`. nft's JSON parser rejects such a string as a service or hostname ("Could not resolve service"), while text loads it as a range, so `eq fields.tcp.dport "1000-2000"` loaded as text and failed as JSON. A word with a hyphen, such as `"echo-request"`, `"admin-prohibited"`, or `"wg-home"`, stays a string.

### Removed

- `toNix`. Command builders and `validate` no longer return unset `null` fields, so `lib.generators.toPretty { multiline = true; }` replaces it. That doesn't clean its input: a raw value's `_type` markers and `null` fields print as written.
- `cleanValue`. The renderers still clean their input, so a raw ruleset with `null` fields or `_type` markers renders as before.
- `types.limitUnit` and `enums.limitUnit`, which no field used. Use `types.limitRateUnit` for a limit's rate unit and `types.byteUnit` for the others.
- `compatibility.priorityIntsDefault` and `compatibility.priorityIntsBridge`. Use `compatibility.prioritiesByFamily.<family>.<hook>`, which holds the symbols nft accepts at each hook.
- `chainTypeFor` and `compatibility.hooksWithOifname`. `compatibility` holds only what nft accepts on load ([ADR 0009](docs/adr/0009-dsl-naming-and-argument-conventions.md)), and the two encoded one consumer's conventions: the chain type a priority suggests, and the hooks where an `oifname` match can succeed, though one in `prerouting` loads. A consumer that needs them can rebuild them on `compatibility.prioritiesByFamily` and `compatibility.validChainPlacement`.
- `dsl.rule`. Use `add.rule`, which takes the same body.
- `within`, a second name for `inSet`. Use `inSet`, which builds the same match.
- `match.eq`, `match.ne`, `match.lt`, `match.gt`, `match.le`, and `match.ge`, second names for the top-level operators. Use `eq`, `ne`, `lt`, `gt`, `le`, and `ge`.
- `match.raw`, and the `match` namespace with it. The top-level operators cover nft's seven match operators; for an operator computed at evaluation, write the raw `{ match = { op; left; right; }; }`, which rule validation checks.
- `expr.mapRef`. `expr.map` and `vmap` add the `@` to a bare map name: write `expr.map key "m"` for `expr.map key (expr.mapRef "m")`. It returned `{ map = "@name"; }`, which nft parses nowhere.
- `reject.icmp`, `reject.icmpv6`, `reject.icmpx`, and `reject.tcpReset`, second forms of `reject { type; code?; }`: write `reject { type = "icmpx"; code = "admin-prohibited"; }` for `reject.icmpx "admin-prohibited"`, and `reject { type = "tcp reset"; }` for `reject.tcpReset`.
- `xt`, which built a statement nft rejects as JSON input. `types.statementBodies.xtBody` still types its Read-back.
- A table tree's top-level `elements` key, which named each set twice, as `elements.s = { elements = [ … ]; }`, and block form's `table elements` Refusal with it. Give a set or map its elements in its body, as `sets.s.elements = [ … ]`, or add them to a set defined elsewhere with `add.element` in a `dsl.ruleset`.
- `types.matchStatement`, a second name for `types.statementOf [ "match" ]`. Use `statementOf [ "match" ]`, which builds the same type.
- `types.taggedExpression`, a second name for `expressionOf` over every expression tag. Use `types.expression`, or `types.expressionOf` for selected tags.
- `expr.meta` and `expr.socket`, second names for Field leaves: they take only a key, and `fields.meta` and `fields.socket` have a leaf for every key the schema allows. Use the leaf, such as `fields.meta.mark` for `expr.meta "mark"`.
- The single-tag object types `types.objects.table`, `chain`, `rule`, `set`, `map`, `element`, `flowtable`, `counter`, `quota`, `ctHelper`, `limit`, `ctTimeout`, `ctExpectation`, `ctCount`, `secmark`, `synproxy`, `tunnel`, `metainfo`, and `ruleset`, so `types.objectBodies` holds bodies only, like `types.expressionBodies` and `types.statementBodies`. Use a command's object union, such as `types.addObject` or `types.readBackObject`, which takes the same tagged shapes.
- `types.statements.synproxyAnonBody`, the inline synproxy form alone. Use `types.statementBodies.synproxyBody`, which takes it and the reference forms.
- The element `stmt` field and the `stmt` argument of `expr.elem`. nft's JSON parser ignores element statements, so seeded element counters loaded as fresh ones, and elements of a set that declares no statement loaded without any. Declare the statement on the set, as in `statements = [ counter.auto ]` (`stmt` in JSON), to give each element its own counter.
- `fields.icmpv6.packetTooBig`, a field nft doesn't have. Use `fields.icmpv6.mtu`.
- `fields.ct.count`. `ct count` is a statement (`ctCount`), not a ct key.
- `fields.meta.ibriport`, `obriport`, and `secpath`, nft's aliases for `fields.meta.ibrname`, `obrname`, and `ipsec`, which nft lists under those names. `types.metaKey` still accepts the aliases, so `validate` takes them as raw input.
- The leaves nft loads only with a refinement: every `fields.fib` and `fields.ipsec` leaf, and `fields.ct.saddr`, `daddr`, `proto-src`, `proto-dst`, `protoSrc`, and `protoDst`. A FIB result needs `saddr` or `daddr` among its flags, and these ct and ipsec keys need a direction, so nft rejected each leaf as written. Build them with `expr.fib`, `expr.ct`, and `expr.ipsec`, as in `expr.ct { key = "saddr"; dir = "original"; }`.
- The `.plain` variants of `log`, `queue`, `reject`, `masquerade`, and `redirect`. Use the empty body, for example `log { }`.
- Command builders for commands nft rejects: `list.rule`, `list.element`, `list.flowtable`, `list.synproxy`, `list.metainfo`, `list.ctCount`, and `reset.rule`, whose JSON form fails with "Operation not supported".
- Command builders for commands nft mishandles: `delete.ctExpectation` and `destroy.ctExpectation` (they delete the whole table), `list.ctExpectation` (it lists the table), `delete.ctTimeout`, `destroy.ctTimeout`, and `list.ctTimeout`, and `delete.ctCount` and `destroy.ctCount` (nftables 1.1.7 aborts). The [schema coverage](docs/spec-coverage.md#commands-nft-mishandles) lists each misbehaviour.
- Tunnel builders: `create.tunnel`, `delete.tunnel`, `destroy.tunnel`, `list.tunnel`, and the table-tree `tunnels` kind. nft mishandles each tunnel command; see the [schema coverage](docs/spec-coverage.md#commands-nft-mishandles).

### Fixed

- `dsl.ruleset` throws when a reset of a counter, quota, set, map, or rule is not its last command, as `types.ruleset` does, whether a builder or a raw attrset made it. nft resets nothing for one placed earlier and still exits 0.
- `toJson` gives a rule command without `expr`, such as a raw `destroy.rule`, the empty list, which nft's JSON parser requires on a rule even where it ignores it. It rendered the rule without `expr`, so a raw `destroy.rule` loaded as text but not as JSON.
- `dsl.ruleset` splices the commands of a ruleset passed as a child in place, so `dsl.ruleset [ base extra ]` composes two rulesets, `base`'s commands then `extra`'s. It nested one ruleset inside the other, which nft rejects. A non-list argument throws `nix-nftypes: dsl.ruleset: expected a list of children, got …`, naming what it got, instead of a bare Nix type error, and the invalid-child error names what it got and asks for a Table tree, ruleset, command attrset, or list.
- `toJson`, `toText`, and `toTextPretty` throw for a raw `{ nftables = [ … ]; }` among a ruleset's commands and ask for `dsl.ruleset`, which splices it in. `toJson` rendered it as JSON nft rejects.
- `toJson`, `toText`, and `toTextPretty` throw for a Table tree passed where a ruleset belongs, alone or among its commands, and ask for `dsl.ruleset`. `toJson` rendered it with its internal marker, as JSON nft rejects, and the text errors didn't say what was wrong.
- The home-router example loads. Its input chain had a `flow` statement, which the kernel takes only in a forward chain, and its flowtable was named `offload`, which text can't spell; it's now `fastpath`.
- Text of a listed ruleset leaves out its `metainfo`, which nft's JSON parser ignores. It wrote a `metainfo` line, which nft rejects.
- Text leaves the `handle` off a listed rule, which nft's JSON parser ignores, so a Read-back with rules loads as text. It wrote `rule … handle 7`, which text reads as a position, so the load failed with "No such file or directory".
- Text writes an explicit `==` for the JSON match op `"=="`, such as `tcp dport == 22`, and keeps the implicit form, such as `tcp flags syn`, for `"in"`. It omitted the `==`, so `eq tcp.flags "syn"` loaded as an any-bit test that also matched SYN-ACK.
- Text brackets an IPv6 NAT, snat, or tproxy address that a port follows, as in `dnat to [2001:db8::1]:80`, including each end of an address range. It wrote `2001:db8::1:80`, which loaded as a different address with no port. A prefix that a port follows now ends with a space (`10.0.0.0/24 :80`), which nft needs to parse it.
- Text parenthesises a binary operand after the first when its precedence is equal to the operator's or lower, as in `meta mark << (1 << 2)`. Only lower precedence got parentheses, so this loaded as `meta mark << 1 << 2`, which is `meta mark << 3`.
- Text renders a ct expectation `timeout` in milliseconds, as JSON does. It rendered seconds, so `timeout = 60` loaded as one minute instead of 60 ms.
- Block form (`toTextBlock`, `toTextBlockPretty`) keeps the table's `flags` and `comment`. It dropped them, so a `dormant` table loaded active.
- Text writes the icmpv6 field `parameter-problem` as `param-problem`, the only spelling nft's text parser accepts; `parameter-problem` failed to parse. It renders the arp address fields `saddr ether`, `saddr ip`, `daddr ether`, and `daddr ip`, which it refused as unsafe tokens.
- Text quotes interface names: set and map elements whose type or typeof key is `ifname`, the interface-name parts of concatenations, the right side of interface-name matches, vmaps, and map lookups, and the devices of chains, flowtables, and `dup` and `fwd` statements. Written bare, `010`, `0x10`, and `a|b` loaded as `8`, `16`, and `c`, `$lan` took a host `define`, and `1e5` and `-x` failed to parse.
- Text declares a typeof set or map with `typeof`, as in `typeof ip saddr . tcp dport` and `typeof ip saddr : meta mark`. It wrote `type typeof …`, which nft rejects.
- Text spells limits as JSON loads them. A `packets` rate unit is a packet rate, written without a unit; it wrote `10 packets/second`, which nft rejects. A byte rate's burst defaults to bytes; it wrote `burst 5 packets`, which nft rejects. A burst of 0 is left out, as the default it is; inline `burst 0 packets` failed to load.
- Text writes a quota's units, which default to bytes, as in `quota 100 bytes`, and a quota object without `bytes` as `0 bytes`. It wrote `quota 100` and an empty quota object, which nft rejects.
- Text writes a NAT `netmap` flag as `snat ip prefix to …` and a `concat` type flag as `snat ip addr . port to …`. It appended the flags after the address (`snat to 10.0.0.0/24 prefix`), which nft rejects. The `prefix` and `interval` type flags aren't written: the first only changes how nft lists the statement, and nft derives the second from the map.
- Text writes one `flags` clause per log flag group, as in `log flags tcp sequence,options flags skuid`, and `last used` as a time: `last used 1000ms`, or `last used never` for -1. It wrote `log flags tcp sequence tcp options` and `last used 1000`, which nft rejects.
- Text writes an extension header existence check as `exthdr frag`. It wrote `frag`, which nft rejects.
- Text writes `fwd ip to 192.0.2.1 device "eth0"` for a next hop, and `queue to <expression>` for a queue number given by an expression such as `symhash`. It wrote `fwd to 192.0.2.1 family ip via eth0` and `queue num symhash …`, which nft rejects. A queue with flags and no number is `queue bypass`, as `queue flags bypass` needs a number.
- Text quotes a negative integer, as in `meta mark "-1"`, the symbol JSON loads. Bare, nft read the `-` as a syntax error.
- Text separates a synproxy object's values with `;`, as in `mss 1460; wscale 7; timestamp sack-perm`, in its body and in `create synproxy`. It wrote `mss 1460 wscale 7`, which nftables 1.1.7 loads with `wscale` 0, or 8 after `timestamp`, and put the flags in a statement of their own, which nft rejects.
- Text writes an `snat` or `dnat` with a `family` and a `port` but no address without the family, as in `snat to :80`, which loads as JSON loads it. It wrote `snat ip to :80`, which nft rejects. nft's JSON parser loads the table's family there: in an inet table it ignores the NAT family, and in an ip or ip6 table it fails on another one, which text refuses, naming the field (`nat family`).
- Text writes a counter object's counts as the pair nft's text takes, `packets 5 bytes 0`, when only one is given; JSON loads the missing one as 0. It wrote `packets 5` alone, which nft rejects. `create counter` takes the counts positionally; it wrote them in braces, which nft rejects.
- Text writes `create secmark` with its context positionally, as in `create secmark inet t s "system_u:object_r:ssh_server_packet_t:s0"`. It wrote a brace body, which nft rejects. A `create secmark` with a comment or without a context is a Refusal, naming the field: the positional form has no comment clause and requires the context.
- Table-tree expansion adds stateful objects before sets and maps: counters, quotas, limits, ct helpers, ct timeouts, ct expectations, secmarks, synproxies, and ct counts. Objects followed the kinds that sort before them, so a map of quotas, synproxies, secmarks, or ct helpers came before the objects its elements name, and its JSON and imperative text failed to load with "No such file or directory".
- A table tree throws naming the table and the key when its `chains`, the named objects of one kind, such as its `sets` or `counters`, or a chain's `rules` has the wrong type, in `dsl.ruleset` and block form alike: `nix-nftypes: dsl.table inet.fw: sets: expected an attribute set of set bodies, got a list`, or `chains.input.rules: expected a list of rules, got a set`. It failed with a bare Nix error, such as "expected a set but found a list", that named neither.
- Text declares a map of ct helpers, ct timeouts, or ct expectations with a typeof key, as in `typeof tcp dport : ct helper`. It refused the value as an unsafe datatype. With a datatype key, which nft lists but can't parse, text refuses the map, naming the field (`map type`).
- Text writes a tunnel statement as `tunnel name "vxlan0"`. It wrote `meta tunnel set "vxlan0"`, which nft rejects.
- Text quotes an OS fingerprint on the right side of an `osf name` or `osf version` match and in a typeof set of one, as in `osf version == "Linux:3.0"`. It wrote the string bare, and nft's text failed to parse `Linux:3.0`.
- `toJson` and the text renderers keep a verdict that carries a `_type` marker: `{ accept = null; _type = …; }` cleans to `{ accept = null; }`. It became `{ }`.
- A wrong value in an expression field, such as a match's `left`, is a type error naming the field. `types.expression` described itself in its own description, so evaluation failed with "infinite recursion encountered" instead.
- `vmap` and `expr.map` wrap a list given as data in an anonymous map, `{ set = list; }`, as `inSet` wraps a list in an anonymous set, so `vmap fields.tcp.dport [ [ 22 accept ] [ 80 drop ] ]` loads. They passed the bare list on, which nft's JSON parser rejects and text rendered as `tcp dport vmap 22, accept, 80, drop`, which nft can't parse.
- Text writes every ct key of `types.ctKey` as nft lists it, the keys whose name holds a space included, as in `ct original ip saddr 192.0.2.1`. It refused `ip saddr`, `ip daddr`, `ip6 saddr`, and `ip6 daddr` as unsafe tokens, so a rule that `toJson` rendered threw in `toText`. Raw input with any other ct key holding a space is still refused.
- `validate`, every DSL builder, a Table tree, `dsl.ruleset`, and the renderers throw on a module property, such as `lib.mkIf`, `lib.mkMerge`, `lib.mkDefault`, or `lib.mkBefore`, naming where it sits: ``nix-nftypes: validate: nftables.0.add.table: got lib.mkMerge, which only the module system resolves; build the value with lib.optional, lib.optionalAttrs, or `//` ``. The module system checked the resolved value but returned the property, so `validate` passed it and the renderers wrote it as `{"contents": …}` or `{"condition": …}`, and text dropped a field JSON kept.
- `toJson`, `toText`, `toTextPretty`, and `dsl.ruleset` throw for a ruleset entry that is not one command, a verb holding one object kind, or one listed object, naming the entry: ``nix-nftypes: toJson: nftables.1: `add` holds chain, table, but nft runs only the first; give each its own command``. nft's JSON parser runs only the first verb or kind of an entry with several and still exits 0, so `toJson` emitted a chain nft never added, while text refused it. A statement, such as `dsl.accept`, a Table tree's body without `dsl.table`, and `{ }`, as `lib.optionalAttrs false` returns, throw too; `toJson` rendered them as JSON nft rejects.
- A rule across a body's fields holds for the merged value of an option that several modules define: a delete Selector's one of `name` and `handle`, a chain's placement, a NAT body's address or port, a ct, FIB, or IPsec expression's Refinement, and a ruleset's reset as its last command. The module system checked each definition alone, so two modules could merge into a Selector with both a name and a handle, or a reset before another command, and a base chain whose `policy` came from a second module failed.

## [0.1.0] - 2026-10-13

First release. The [API reference](docs/api.md) documents the library's exports, and the [glossary](GLOSSARY.md) defines the project's terms.

### Added

- Schema types under `types` that model libnftables JSON and validate attrsets through `lib.evalModules`:
  - `ruleset`, the `{ nftables = [ … ]; }` envelope, and `command`, one `add`, `create`, `insert`, `replace`, `delete`, `destroy`, `list`, `flush`, `reset`, or `rename` command.
  - `expression`, `statement`, and the per-variant submodules under `types.expressions`, `types.statements`, and `types.objects`, including the named `ct count` object from nftables 1.1.7.
  - `statementOf` and `expressionOf`, which restrict an option to selected tags.
  - Primitive types such as `family`, `hook`, `chainType`, `ifname`, and `nftQuotedString`, with the values of each enum type under `enums`.
- A DSL under `dsl` that builds the same schema-shaped values:
  - Field leaves such as `fields.tcp.dport` and `fields.ct.state`, the raw `payload` helpers, and expressions under `dsl.expr`, such as `concat`, `prefix`, `range`, `set`, `map`, and `jhash`.
  - Match operators such as `eq`, `inSet`, and `within`, verdicts, and statements such as `counter`, `limit`, `log`, `dnat`, `meter`, and `ctCount`. The `counter`, `quota`, `limit`, `synproxy`, and `ctCount` statements reference a named object by name or through a map expression (`quota.ref (expr.map { … })`).
  - `dsl.table`, which builds a table tree: one table's options, chains with their ordered rules, and named objects, such as `sets`, `counters`, and `ctCounts`. It checks each entry's scope against its table and chain, and validates every assembled body against the schema when output is requested.
  - `dsl.ruleset` and the command builders `flush*`, `rule`, `create`, `delete`, `destroy`, `list`, `reset`, `replace`, `insert`, and `rename.chain`, with a builder for each object kind, such as `create.ctCount`.
- Renderers, pure functions that neither call `nft` nor validate their input:
  - `toJson`, libnftables JSON for `nft -j -f`, and `toNix`, Nix syntax for inspection, both after cleaning (`cleanValue`).
  - `toText` and `toTextPretty`, imperative nftables text for `nft -f`. They render the `ct count` object as `ct count NAME { over|until N; }` and a map-expression reference as `quota name tcp dport map { … }`.
  - `toTextBlock` and `toTextBlockPretty`, the contents of one table tree without the `table { … }` wrapper, the form that `networking.nftables.tables.<name>.content` takes.
  - The text renderers refuse a string that is not nft-safe, such as a comment containing `"`, instead of escaping it ([ADR 0004](docs/adr/0004-refuse-unsafe-text.md)).
- Compatibility helpers `resolvePriority`, `priorityNameOf`, `chainTypeFor`, and `validChainPlacement`, and the static family, chain-type, hook, and priority tables under `compatibility`.
- Error messages prefixed with the project name, `nix-nftypes:`.
- `packages.<system>.nftables-source`: the patched source, the nftables release source with every nixpkgs patch applied, which the nixpkgs `nft` binary is built from.
- Checks for `x86_64-linux` and `aarch64-linux`:
  - Evaluation-only nix-unit suites.
  - Live tests, which run as VM tests with the nixpkgs `nft`. They parse selected JSON and text renderings with `nft -c`, load selected cases through JSON and through text and compare the listed rulesets, and validate the read-back of loaded cases against `types.ruleset`. The VM tests need KVM, so a plain `nix flake check` does too.
  - Source tests against the patched source: the enum tables and tags extracted from the parser, the upstream statement corpus, and the provenance of the source against the nixpkgs `nftables` package.
- CI through the [project policy](https://github.com/petohorvath/nixos-project-policy/blob/v0.6/POLICY.md) `v0.6`, which builds every check with the locked `nixpkgs` and with the policy's stable and unstable pins. A daily source watch keeps a drift issue open for each pin whose patched source differs from the locked one ([`docs/upstream-sync.md`](docs/upstream-sync.md)).
- MIT license.

Known limits:

- The schema follows the nftables that nixpkgs packages, 1.1.6 in the locked `nixos-26.05`, rather than upstream nftables. [`docs/spec-coverage.md`](docs/spec-coverage.md) lists the known differences, and [`docs/dsl-coverage.md`](docs/dsl-coverage.md) lists what the DSL reaches.
- nftables 1.1.6 rejects `ct count` objects and references, so no live test exercises them. The corpus check covers their statement shapes only with a pin that carries nftables 1.1.7.
- Text output cannot represent every value that JSON can; [`docs/text-coverage.md`](docs/text-coverage.md) records the gaps.
- The compatibility helpers check only the static tables. They do not inspect kernel versions, modules, devices, or runtime state, so an `inet` or `netdev` ingress chain that `validChainPlacement` accepts can still require `dev`.
