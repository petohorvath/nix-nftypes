# Give the public API one set of naming and argument conventions

The 0.1.0 DSL mixed `flush*` builders with `verb.kind` namespaces, `snake_case` with camelCase field names, and positional with attrset arguments for the same fields. 0.2.0 applies one set of rules everywhere, so callers can predict a builder's shape from its kind:

- Each command verb is a `<verb>.<kind>` namespace, and each builder takes one object body. `add`, `create`, `delete`, `destroy`, `flush`, `list`, and `reset` are generated from the object-kind registry, and each offers only the kinds that nft runs as written for that verb. A verb with one kind is a namespace too, so its builder reads like nft's command: `insert.rule`, `replace.rule`, and `rename.chain`.
- Each builder has one name, in the namespace of what it builds. No builder or type is a second name for another, as `within` was for `inSet`, `match.eq` for `eq`, `expr.meta "mark"` for `fields.meta.mark`, and `types.matchStatement` for `types.statementOf [ "match" ]`. No DSL name is both a statement and an expression constructor or a command verb: a statement whose tag one of them already names takes a `Stmt` suffix, as `setStmt`, `mapStmt`, and `resetStmt` do. An operator is named for the test it makes, as `hasAnyFlag` is for nft's `in`, which matches when any of the given flags is set, and a binary operator for the operation it computes, in camelCase as `builtins.bitAnd` is: `expr.bitAnd` and `expr.shiftLeft`. Expression constructors sit under `expr`, the payload ones (`expr.payload`, `expr.payloadRaw`, `expr.payloadTunnel`) included, and the compatibility helpers sit under `compatibility` with the tables they read.
- Every DSL field name is camelCase. The DSL renames it to the JSON key, whether that key uses a hyphen (`queue-threshold`) or an underscore (`rate_unit`). A name that is a Nix keyword takes a trailing underscore.
- A builder takes positional arguments only when every argument is required and there are at most two, as in `eq left right`, `vmap key data`, and `counter.ref name`. Every other builder takes one attrset. `dsl.table family name body` is the one exception, because it mirrors nftables' `table inet filter { … }`. The rule covers `dsl` builders, not the compatibility helpers: `compatibility.chainTypeFor family hook priority` and `compatibility.validChainPlacement family chainType hook` are lookups in the placement tables, and take that table's three keys positionally.
- A Field leaf is an expression nft loads as written in some rule, though the rule can need a table family or hook, as `fields.rt.nexthop` needs an ip or ip6 table. A key that nft loads only with a Refinement has no leaf, and its `expr` constructor builds it: a FIB result needs `saddr` or `daddr` among its flags, and every IPsec key and the conntrack keys `saddr`, `daddr`, `proto-src`, and `proto-dst` need a direction, so `expr.fib`, `expr.ipsec`, and `expr.ct` build them. An `expr` constructor exists only for a form a leaf can't express, so meta, socket, and tunnel expressions, which take only a key, have their leaves only. A group of leaves for one keyed expression is named for its JSON tag, as `fields.ct`, `fields.meta`, and `fields.tunnel` are.
- A statement whose fields are all optional takes `{ }` for its empty form. Named variants cover forms an attrset cannot express: `.ref name` for a named object and `.auto` for the JSON null body. `counter` and `last` are not such statements: nft parses an inline counter only with both `packets` and `bytes`, and rejects an empty `last` body, so `counter { }` and `last { }` throw and point to `counter.auto` and `last.auto`.
- Every reference to a named object follows one rule. A builder takes the name with or without its `@` and emits the spelling nft's JSON parser looks up in that position: `"@name"` for a set, map, or flowtable, and the bare name for a stateful object, which nft looks up as written. A bare string where a reference is required either normalises under this rule or throws pointing at the reference builder; it never passes through. Every stateful object reference is a `.ref` variant, `ctHelper.ref "ftp"` as much as `counter.ref "c"`, and a statement with no other form throws when called. `expr.setRef` and `expr.mapRef` both return the `"@name"` string, which nft takes in a match, a map lookup, and a vmap, and lists.
- `delete`, `destroy`, `list`, `flush`, and `reset` select an object by `family`, `table`, and `name`, plus `handle` where nft takes one, and demand no field nft ignores for the verb. A field nft does require stays required: a rule's chain and positive handle, and an element's value.
- Every library error starts `nix-nftypes: <API>: `, where `<API>` is what the caller called: a builder's path under `dsl` (`dsl.create.ctCount`), `dsl.table <family>.<name>` for a table tree, followed by the field's path in it, `text` for the text renderers, `types.statementOf`, or a helper such as `compatibility.resolvePriority`. The module system's own errors name the option path, which for a command builder starts with the builder, as in `dsl.create.ctCount.name`. A text Refusal also ends with its field ([ADR 0004](0004-refuse-unsafe-text.md)).
- Every `types.*` name is camelCase, capitalised word by word, as in `chainType`, `ctL3Proto`, and `tcpUdpProto`. An enum or primitive type is named for its values when they mean the same wherever nft takes them (`comment`, `family`, `ifname`, `timeUnit`). Otherwise it is named for the tag or object kind whose field it types, then for that field (`chainPolicy`, `ipsecKey`, `numgenMode`, `ctDirection`); when several tags or kinds share the field, the name starts with what they share or with the first of them, as a shared body's does (`natFlag`, `setFlag`). A body namespace is named for what it holds (`expressionBodies`), a command's object union for its verb (`deleteObject`), and the body of one command for its verb and then its kind (`insertRuleBody`, `renameChainBody`, `selectSetBody`), so names that differ by a letter don't name different things. The Read-back object union is `readBackObject`.
- `types.expressionBodies`, `types.statementBodies`, and `types.objectBodies` hold bodies only, and every body is `<kind>Body`; the namespace tells the layers apart, as in `types.objectBodies.setBody` and `types.statementBodies.setBody`. A body that several tags share is named for what they share (`natBody`, `binaryOpBody`, `objectRefBody`, `verdictTargetBody`), or, without a common name, for the first of them (`masqueradeBody`, which `redirect` also takes). Every other body name puts its parent first: a variant or a nested part of one tag's body puts the tag first (`payloadRawBody`, `tcpOptionNamedBody`, `tunnelVxlanBody`), as the DSL does (`expr.payloadRaw`), and the body of one command puts its verb first (`flushRulesetBody`, `insertRuleBody`, `selectSetBody`). A command's body is named for its verb even when its fields match another body's, so `insertRuleBody` and the Read-back `ruleBody` are two types, not one type under two names. A body that both the expression and the statement layer take is listed in both namespaces, as `verdictTargetBody` is for the verdict expressions and for `jump` and `goto`. A statement body includes the statement's reference forms (`counterBody`, `ctCountBody`); its inline part alone is not exported. A tagged object is typed by its command's union (`addObject`, `insertObject`, `readBackObject`), not by a per-kind wrapper.

## Considered options

- Deprecated aliases with warnings, removed in a later release. 0.1.0 had been out for a day and had almost no users, so one clean break cost less than a deprecation cycle.
- Attrset arguments everywhere except operators. It would have changed `vmap`, `mangle`, and `xt`, which read like their nftables syntax when positional.
- Plain functions for the single-kind verbs, `insert body` and `replace body`. They are shorter, but a builder's shape would then depend on how many kinds nft offers for its verb, and `rename.chain` was already a namespace.
- Stateful object references taken directly, as `ctHelper "ftp"`. `counter`, `quota`, `limit`, `synproxy`, and `ctCount` have inline forms that take an attrset, so they can't also take a name, and `.ref` was already the variant for a named object.
- Leaves that carry a direction in their path, as nft's text does: `fields.ct.original.saddr` and `fields.ipsec.in.reqid`. They would keep the short form, but FIB flags combine freely and fit no path, and adding such leaves later breaks nothing, so they wait for a need.
- One `reset` for the statement and the command verb, the statement as a `__functor` on the verb namespace. It kept the short name, but `reset` was then the one name that was both a statement and a command, and the `Stmt` suffix already resolved the same clash for `set` and `map`.
- A bare `last` value beside `lastUsed used`. The unseeded form stays short, but one statement had two names, and `counter` already carries the same two forms as `counter.auto` and `counter { … }`.
- `match.in_`, after nft's operator token. `in` reads like set membership, which is `inSet`, and says nothing of the flag test.
- One reference shape everywhere, `"@name"`. nft looks a stateful object up by the name as written, so `counter "@c"` names no object; the spelling has to follow the position.

## Consequences

- A bare `flush` value cannot also carry `flush.<kind>` builders, because the value is emitted as JSON. Flushing everything is therefore `flush.ruleset { }`, whose empty body stands for the JSON `null`. For the same reason the unseeded `last` is `last.auto`, not the bare `last`.
- Object bodies, in a table tree or a command builder, still accept the JSON spelling of a key (`rate_unit`, `gc-interval`) because the rename passes unknown keys through. Statement builders reject the JSON spelling as an unexpected argument.
- `inSet` and `notInSet` take a set reference only as `"@name"`: their right side need not be a set, so a bare string is ambiguous and throws, pointing to `expr.setRef`.
- `expr.payloadRaw` and `expr.payloadTunnel` keep their names: `expr.payload` is a plain two-argument function, not a variant namespace that could carry `.raw`. The suffix matches `expr.tcpOptionRaw`.

## Evidence

- `lib/dsl/structure/commands.nix` builds every registry-backed verb namespace with `mkNamespace`; `lib/dsl/internal/rename.nix` holds every rename, `lib/dsl/internal/reference.nix` the reference rule, and `lib/dsl/internal/location.nix` the error prefix.
- `testNoPlainVariants`, the `testCounter*Throws` cases, the `flush.<kind>` and `add.<kind>` cases, the camelCase cases, `testFieldLeavesAreCamelCase`, the `*AtName` reference cases, `testObjectReferenceStatementsUseRef`, `testSelectingVerbsTakeOnlyTheSelector`, `testSingleKindVerbNamespaces`, `testNoFieldLeafNeedsARefinement`, `testExprHasNoKeyOnlyConstructors`, `testResetIsOnlyAVerbNamespace`, `testLastEmptyBodyThrows`, and the `testOpHasAnyFlag*` cases in `tests/unit/dsl-parity.nix`; `testLeafChecksSendTheirFieldLeafAsWritten` in `tests/unit/parse-check-inputs.nix` holds the parse check to sending each leaf unchanged; `tests/unit/public-surface.nix` pins every exported name.
- Measured on nftables 1.1.6 and 1.1.7: `"counter": "@c"` and the other stateful references fail with "No such file or directory", a bare set or map name fails as an unresolved hostname, and `"@s"` and `{ "set": "@s" }` load in a match, a map lookup, and a vmap. The `object-references` Integration case loads every reference built from both spellings. nft ran `list`, `flush`, and `reset` of a set or map, `list` of a limit, and `delete` and `destroy` of a synproxy with the name alone, and a rule delete with handle 0 deleted every rule in the chain (`delete-rule-handle-zero-deletes-every-rule` in `tests/fixtures/nft-misbehaviour.nix`).
- Measured on nftables 1.1.6 with `nft -c`: a FIB result without `saddr` or `daddr` among its flags fails with "fib: need either saddr or daddr", and the conntrack keys `saddr`, `daddr`, `proto-src`, and `proto-dst` (in an ip table) and every IPsec key fail without a direction with "Invalid argument". Each loads with the Refinement. nft rejects `{ "last": {} }` ("Parsing expr array at index 0 failed") and loads `{ "last": null }` and `{ "last": { "used": … } }`. `nft --debug=netlink` shows that the `in` operator on `tcp flags` with `syn` and `ack` compiles to `(flags & 0x12) != 0`.
